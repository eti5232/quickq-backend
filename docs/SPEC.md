# QuickQ — מסמך אפיון (גרסה מאושרת)

## א. תיאור הפרויקט

**שם:** QuickQ, מערכת חכמה לניהול תורים

**מטרה:** לחסוך ללקוחות המתנה מיותרת בחדר ההמתנה. הקליניקה מעדכנת בזמן אמת מי בטיפול, והלקוח רואה מהבית כמה אנשים לפניו, מתי בערך יגיע תורו ומתי לצאת מהבית. אם ביקש, הוא גם מקבל תזכורת במייל.

**קהל יעד:** קליניקות, מרפאות, יועצים ומכונים שעובדים עם תורים, והלקוחות שלהם.

| תפקיד | תיאור |
|---|---|
| 👑 מנהל על (SUPER_ADMIN) | בעל האתר. מאשר פניות הצטרפות, מנהל קליניקות ומשתמשים |
| 🏥 מנהל קליניקה (CLINIC_MANAGER) | מנהל או מזכירה של קליניקה אחת. מנהל את הרופאים, השעות, התורים, התור היומי והצוות |
| 👤 לקוח (CLIENT) | נרשם, קובע, משנה ומבטל תורים, וצופה בתור החי |

**החלטות עיקריות:**
- אנשי מקצוע (רופאים) לא מתחברים למערכת. לכל רופא יש תור משלו, ובקליניקה יכולים להיות כמה רופאים.
- הלקוח בוחר שעה דרך **לוח שנה**, ואחר כך בוחר **משבצת פנויה** מתוך שעות הפעילות של הרופא.
- **"הבא בתור"** מכניס את הלקוח הבא מבין אלה שסומנו "הגיע". מי שלא הגיע מדולג, ותמיד אפשר לבחור לקוח מסוים ידנית.
- **ביטול** אפשרי תמיד. אחרי המועד שהקליניקה קבעה הוא מסומן "ביטול מאוחר", בלי דמי ביטול.
- **שינוי שעה** אפשרי רק אצל אותו רופא, ורק עד המועד שהקליניקה קבעה.
- **תזכורת במייל** נשלחת רק למי שביקש. החישוב לוקח בחשבון את "זמן ההגעה לקליניקה" של הלקוח.
- **הצטרפות קליניקה:** טופס פנייה, אישור של מנהל העל, ויצירה אוטומטית של הקליניקה ושל חשבון מנהל עם סיסמה זמנית.
- **ייבוא CSV** של תורים קיימים.
- **פרטיות:** מסך התור הציבורי מציג מספרים בלבד. תעודת זהות גלויה רק ללקוח עצמו, למנהל הקליניקה שלו ולמנהל העל.
- **בחוץ:** Web Push, חיבור למפות ותשלום דמי ביטול. אלה מוגדרים כפיתוח עתידי.

## ד. מסד הנתונים

| טבלה | מטרה | שדות עיקריים | קשרים |
|---|---|---|---|
| **User** | כל המשתמשים | id PK, role, fullName, email (ייחודי), phone, nationalId (ייחודי), passwordHash (ריק אצל לקוח טלפוני), defaultTravelMinutes, mustChangePassword, isActive, clinicId FK | N:1 Clinic (מנהלים), 1:N Appointment |
| **PasswordResetCode** | קודי שחזור | id PK, userId FK, codeHash, expiresAt, usedAt, attempts | N:1 User (cascade) |
| **Clinic** | קליניקות | id PK, name, category (enum), city, address, phone, description, isActive, changeDeadlineHours (0-168), maxFutureAppointmentsPerProvider (1-20), bookingHorizonDays (1-365) | 1:N Provider, 1:N User, 1:1 JoinRequest |
| **Provider** | אנשי מקצוע | id PK, clinicId FK, fullName, specialty, slotMinutes (5-120), isActive | N:1 Clinic |
| **WorkingHours** | שעות שבועיות | id PK, providerId FK, dayOfWeek (0-6), startTime, endTime ("HH:MM"). ייחודי: (providerId, dayOfWeek, startTime) | N:1 Provider (cascade) |
| **ProviderAbsence** | היעדרות של יום שלם | id PK, providerId FK, date, reason. ייחודי: (providerId, date) | N:1 Provider (cascade) |
| **Appointment** ⭐ | תורים | id PK, providerId FK, clientId FK, startTime, endTime, status (7 ערכים), queueNumber, source, notes (≤500), reminderEnabled, travelMinutes, reminderSentAt, isLateCancellation, arrivedAt, startedAt, completedAt, cancelledAt | N:1 Provider, N:1 User |
| **QueueDay** | מצב היום החי | id PK, providerId FK, date, status (OPEN/PAUSED/CLOSED), openedAt, closedAt. ייחודי: (providerId, date) | N:1 Provider (cascade) |
| **JoinRequest** | פניות הצטרפות | id PK, clinicName, category, city, contactName, email, phone, message, status, rejectReason, clinicId FK (ייחודי), reviewedAt | 1:1 Clinic |

**אילוצי תקינות בשרת:**
- אין חפיפה בין תורים פעילים אצל אותו רופא. הבדיקה רצה בטרנזקציה עם נעילה.
- אין חפיפה בין תורים של אותו לקוח, גם בין קליניקות שונות.
- תור חייב להיות במשבצת חוקית, בשעות הפעילות, לא ביום היעדרות, לא בעבר, ובתוך טווח הימים שהקליניקה מאפשרת. בייבוא CSV מותר גם מחוץ לשעות הפעילות.
- אסור לעבור את מקסימום התורים העתידיים. המגבלה חלה רק על לקוח שקובע בעצמו.
- רק לקוח אחד בטיפול אצל כל רופא בכל רגע נתון, ומעברי הסטטוס מוגדרים מראש.

59 Endpoints. הרשימה המלאה, עם Request, Response, דוגמאות JSON והרשאות, נמצאת ב־Swagger (`/api-docs`) ובקובץ [openapi.json](openapi.json).

| מסד נתונים אמיתי | PostgreSQL + Prisma Migrations |
